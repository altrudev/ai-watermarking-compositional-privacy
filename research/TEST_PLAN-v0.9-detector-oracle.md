## 1. Research purpose

This experiment asks whether access to a synthetic watermark detector can become an inference channel even when each detector response contains no explicit human identity.

The primary question is:

> Does repeated access to richer detector feedback create measurable inference advantage over no-detector or binary-detector controls after query budget, artifact content, auxiliary evidence, and hidden ground truth are controlled?

The experiment does **not** attempt to reproduce Anthropic, Google, OpenAI, Meta, or any other deployed watermark. It does not query production detectors or provider APIs. The watermark and detector are synthetic abstractions designed to isolate disclosure-level effects.

## 2. DDC research boundary

Authorized objects are synthetic artifacts, synthetic watermark families, synthetic key scopes, synthetic epochs/cohorts, synthetic detector scores, synthetic candidate sets, and deterministic transformations generated by this repository.

Prohibited expansion:

- real people or accounts;
- real sessions, provider logs, billing/login records, private conversations, or scraped profiles;
- production watermark detectors or provider APIs;
- recovery of real watermark keys, secrets, or proprietary detector architecture;
- real-person authorship attribution;
- operational bypass instructions against a live service.

Standing distinctions:

- Detection != Provenance != Attribution != Identity Resolution != Authority.
- Detector output != detector architecture.
- Query leakage != key recovery.
- Candidate reduction != evidence creation.
- Watermark removal != anonymization.
- Watermark persistence != content integrity.
- A detected signal != proof that the detected model authored the final semantic claim.
- Synthetic benchmark != deployed-provider behavior.

## 3. External hypothesis-generating evidence

External evidence motivates the question but does not count as evidence for this experiment.

- DITTO (An, Park, Woo, Han; EACL 2026; DOI 10.18653/v1/2026.eacl-long.229) demonstrates authentic-looking watermark spoofing through knowledge distillation and therefore false model-attribution risk.
- Watermark Stealing (Jovanovic, Staab, Vechev; ICML 2024) demonstrates black-box attacks that approximate watermark rules and support spoofing/scrubbing.
- Public-detector-oracle work summarized by CMU shows detector feedback can be used adaptively for removal/spoofing in evaluated watermark schemes.
- STAMP-R (PrivateNLP 2026) and De-Anonymization at Scale (ACL 2026) motivate the separate compositional-privacy proposition that explicit identifiers are not required for authorship linkage.

## 4. Hypotheses and nulls

### H1 — disclosure richness

For equal query budgets, richer detector feedback produces greater inference gain than D1 binary output or D0 no-detector access.

**H1 null:** detector-output richness provides no material gain after controls.

### H2 — adaptive-query advantage

Adaptive queries selected after observing prior detector outputs outperform an identical-budget frozen query sequence.

**H2 null:** adaptivity provides no material advantage.

### H3 — binary boundary leakage

Even D1 binary output may leak structure across repeated near-boundary transformations.

**H3 null:** D1 provides no material advantage over D0 under equal artifacts and auxiliary evidence.

### H4 — mitigation tradeoff

Coarsening, deterministic rate limits, or predeclared output noise reduce inference gain relative to richer detector conditions while preserving useful synthetic provenance detection.

**H4 null:** mitigation does not materially reduce inference gain or destroys detection utility without privacy benefit.

### H5 — compositional gain

Detector access may add marginal candidate-reduction or attribution advantage when combined with weak auxiliary evidence even if detector output alone is insufficient.

**H5 null:** detector access adds no marginal advantage over the otherwise identical auxiliary-evidence condition.

## 5. Synthetic watermark/key-scope conditions

The benchmark uses abstract synthetic watermark scope, not provider emulation:

- K0 — no watermark;
- K1 — global shared signal;
- K2 — provider/model-family signal;
- K3 — rotating epoch signal;
- K4 — cohort/organization signal;
- K5 — synthetic session signal;
- K6 — synthetic account/person-proximal signal;
- K7 — layered scope signal.

K5-K7 are sensitivity-test conditions only. Their presence must not be described as evidence that any provider deploys comparable scopes.

Hidden truth records contain exact K condition and scope identifier. Public detector responses must never directly emit those hidden labels except where the disclosure condition explicitly allows a coarse category that is derived without exposing the exact hidden identifier.

## 6. Detector disclosure conditions

- D0 — no detector access.
- D1 — binary output only (`DETECTED` / `NOT_DETECTED`).
- D2 — coarse confidence band (`LOW`, `MEDIUM`, `HIGH`).
- D3 — scalar confidence score rounded to 3 decimals.
- D4 — scalar score plus coarse span-local contribution bins; no token truth labels.
- D5 — score plus explanatory metadata limited to synthetic detector observables; no key/scope/session/account identifiers.
- D6 — mitigated detector: coarse bands + deterministic query budget + predeclared bounded noise.

The same hidden detector function must underlie D1-D6. Disclosure level changes only what is revealed, not the underlying truth-generation process.

## 7. Query modes and budgets

Two query policies are frozen:

- QF — frozen sequence: edit candidates are generated before any detector response is observed.
- QA — adaptive sequence: the next edit is selected from a frozen candidate-edit set using only information already revealed by prior detector responses.

Primary budgets: `1, 4, 8, 16` detector queries per artifact.

A compared cell is invalid if actual detector calls differ between the two conditions being compared, except D0 which has zero access by definition. For D0 comparisons, the query policy still generates the same candidate-edit sequence without detector evaluation so artifact-generation effort is held constant.

No condition may query indefinitely or stop early after success for the primary analysis. Early success may be recorded descriptively, but every primary cell consumes its predeclared budget unless the D6 rate-limit condition blocks calls by design.

## 8. Artifact populations

Three deterministic scenarios are predeclared:

| Scenario | Candidate scopes | Unknown/holdout scopes | Artifacts per scope | Seed |
|---|---:|---:|---:|---:|
| S1 | 8 | 8 | 12 | 1901 |
| S2 | 16 | 8 | 12 | 2903 |
| S3 | 24 | 12 | 12 | 3907 |

Scopes are synthetic labels, not people. Where K6 is evaluated, identifiers remain under the `syn-` namespace and are never mapped to real identities.

Calibration and holdout scope sets are disjoint. Thresholds/decision rules may not use holdout artifacts.

## 9. Artifact states

Each artifact is evaluated in:

- A0 — original synthetic derivative;
- A1 — paraphrase;
- A2 — summarize;
- A3 — paraphrase -> summarize -> model-edit;
- A4 — spoof-proxy transformation that alters the synthetic detector statistic without copying hidden truth labels.

A4 is not an implementation of DITTO and must not be described as such. It is a controlled false-signal condition used to test attribution integrity.

## 10. Auxiliary evidence conditions

- E0 — artifact text only;
- E1 — weak semantic/stylometric similarity only;
- E2 — coarse synthetic time window only;
- E3 — E1 + E2;
- E4 — provenance class only, without detector queries;
- E5 — E1 + E2 + provenance class.

Detector access is added orthogonally to these evidence states. The primary quantity is the marginal change caused by detector access relative to the same E condition without detector access.

## 11. Synthetic detector model

The implementation must define a deterministic hidden score `s in [0,1]` based on synthetic watermark statistics plus controlled transformation effects.

Requirements:

1. score computation cannot use public-facing candidate IDs or hidden attribution truth strings;
2. exact hidden scope labels cannot appear in emitted detector responses;
3. D1-D6 derive from the same `s`;
4. bounded noise in D6 is deterministic from experiment seed + artifact + query index so replay is exact;
5. K0 negative controls must not receive systematic positive bias;
6. A4 spoof-proxy must alter only declared observable statistics, not hidden labels;
7. response generation must be separable from downstream inference so detector output cannot directly call the evaluator.

## 12. Candidate-edit set

For each artifact/query position, generate the same bounded candidate-edit set before detector disclosure:

- synonym substitution proxy;
- punctuation-neutral edit proxy;
- short phrase deletion proxy;
- semantic-preserving reorder proxy;
- paraphrase-strength increment proxy.

The experiment must retain an edit-distance/semantic-utility proxy so improvements cannot be obtained merely by destroying the artifact.

QA may choose among the frozen candidates using detector feedback. QF chooses from the same candidates using a deterministic order independent of detector feedback.

## 13. Primary metrics

### M1 — detector information gain

Entropy reduction over hidden synthetic scope class from prior to posterior candidate distribution using only permitted observations.

### M2 — candidate reduction

Change in median candidate-set size attributable to detector access relative to identical E/Q/artifact controls.

### M3 — hidden-scope classification advantage

Accuracy above the no-detector baseline for K-class, epoch, or cohort classification. Exact secret-key recovery is not measured and must not be inferred from this metric.

### M4 — adaptive advantage

Difference between QA and QF at equal query budgets.

### M5 — spoof/removal optimization advantage

Change in final hidden detector score relative to the frozen-query control, reported separately for downward (removal-proxy) and upward (spoof-proxy) optimization.

### M6 — false-attribution rate

Rate at which an artifact from an unknown synthetic scope is accepted as belonging to a represented synthetic scope after the downstream attribution gate.

### M7 — marginal compositional attribution gain

`delta = performance(E + detector) - performance(E without detector)` under otherwise identical conditions.

### M8 — utility retention

Semantic/content utility proxy retained after the query/edit process. Any attack-like gain below the predeclared utility floor is reported separately and cannot satisfy the primary optimization gate.

## 14. Predeclared materiality thresholds

A detector condition is `MATERIAL_INFERENCE_GAIN` only if all apply in the relevant comparison:

- median candidate-set reduction >= 20%;
- or hidden-scope classification accuracy improves by >= 10 percentage points over its matched control;
- or entropy reduction improves by >= 0.20 bits per artifact;
- and the effect appears in at least 2 of 3 scenarios;
- and median utility retention >= 0.80.

`BINARY_ORACLE_LEAKAGE_OBSERVED` requires D1 to satisfy a materiality condition against D0 in at least 2 scenarios at budget >= 8.

`ADAPTIVE_ADVANTAGE_OBSERVED` requires QA to improve a primary inference/optimization metric by >= 10% relative (or >= 0.10 absolute for bounded [0,1] metrics) against QF at the same budget in at least 2 scenarios.

`MITIGATION_REDUCES_LEAKAGE` requires D6 to reduce the relevant leakage metric by >= 25% relative to D3/D4 while retaining >= 80% of clean synthetic detection utility.

No matrix-wide positive label is allowed if more than 20% of core cells are invalid or if any control category fails.

## 15. Open-set attribution gate

The downstream attribution layer must preserve the v0.8 distinction between best match and sufficient match.

At minimum:

- known and unknown synthetic scope cohorts are disjoint;
- accepted attribution requires both score and margin thresholds;
- thresholds are calibrated only on calibration cohorts;
- unknown holdout scopes remain unseen until evaluation;
- single-candidate outputs abstain rather than manufacture confidence;
- false-attribution events are retained individually.

The exact v0.8 thresholds are not imported as universal constants. v0.9 may reuse the structural procedure but must calibrate only on its own predeclared calibration partition.

## 16. Controls

C1 — truth-label independence: changing hidden labels after observable construction must not change detector score or emitted response.

C2 — response redaction: exact hidden scope/session/account identifiers must never appear in D1-D6 output.

C3 — same-detector parity: D1-D6 must map from the same hidden scalar score for a given query before disclosure transformations.

C4 — equal-budget control: matched QA/QF comparisons make exactly the same number of detector calls.

C5 — frozen-edit control: QA and QF receive the same candidate-edit set at every step.

C6 — K0 negative control: no-watermark artifacts must not show systematic positive watermark bias.

C7 — non-adaptive sham: random/frozen selection cannot access prior responses.

C8 — deterministic replay: repeated complete execution from identical bytes/seeds yields byte-identical canonical serialization.

C9 — calibration isolation: holdout labels/scores never participate in threshold selection.

C10 — spoof-proxy isolation: A4 cannot copy hidden scope labels into observable features.

C11 — response stability accounting: repeated identical queries must either return the same result or only the predeclared D6 deterministic noise variation; uncontrolled nondeterminism invalidates the cell.

C12 — utility guard: edits that fall below the utility floor cannot satisfy primary spoof/removal success gates.

## 17. Failure gates

The following invalidate a run or comparison:

- any real-person or production-provider data enters the experiment;
- any hidden truth label is directly emitted or encoded into a public detector feature;
- unequal query budgets in a matched comparison;
- adaptive policy receives information unavailable under its declared detector condition;
- calibration/holdout contamination;
- post-hoc threshold or materiality tuning;
- implementation changes protocol matrix after observing canonical results;
- nondeterministic replay where deterministic replay is required;
- source bytes executed cannot be identified exactly.

## 19. Claim boundaries

A positive result may establish only that detector-mediated inference leakage occurred in this synthetic benchmark under the declared abstraction.

It must not be reported as proof that:

- Anthropic, Google, OpenAI, Meta, or another provider leaks user identity through a detector;
- a provider uses account/session/cohort-specific keys;
- a real watermark key can be recovered;
- a real person can be deanonymized from a production detector;
- watermarking is universally unsafe or useless;
- detector access itself authorizes attribution, authorship, ownership, responsibility, or enforcement action.

A negative result must not be reported as proof that public detector APIs are privacy-safe. It means only that this benchmark did not establish the predeclared effect.
